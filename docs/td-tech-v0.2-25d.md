## 2. 斜俯透视方案

### 2.1 坐标系

- **世界格**：x ∈ [0, 9)，y ∈ [0, 16)，单位是格；格中心是 (c+0.5, r+0.5)。z 是离地高度，单位也是格（地面单位 z=0，斥候鹰 z≈1.0，弹道按抛物线算 z）。
- **设计坐标**：720×H 的竖屏画框，H 默认 1280（见 2.6）；所有 HUD、环形菜单、Phaser 世界都用这一套。
- **客户端坐标**：浏览器 CSS 像素。只有 `viewport.ts` 负责客户端坐标和设计坐标之间的换算。

### 2.2 投影公式（世界 → 设计坐标）

参数（放在 `data/view.json`）：

| 参数 | 值 | 含义与依据 |
|---|---|---|
| S0 | 72 设计 px | s=1 时 1 格宽。为什么不是 80：最近一行 s=1.15，9 格×80×1.15=828 > 720，边列塔基会出画（M1-p11 (0,11) 左缘到 −11 px，p14 (8,13) 右缘到 731）。72 是 M1 现有塔基都完整在画内的最大值（p14 右缘 711.5） |
| s(y) | 0.75 + 0.40·(y − 0.5)/15 | PRD V0.2 3.1：最远一行 0.75，最近一行 1.15。按脚底 y 连续取值，在格中心正好等于 PRD 的 r/15 |
| k | 0.82 | 地面纵向压缩比 = sin 55°。README 写的俯角约 55°；PRD 射程椭圆也写 0.82。概念图里塔基的椭圆量出来扁到 0.4～0.5，但那是生图模型画的，不精确，所以以 README 和 PRD 为准 |
| kz | 0.57 | 高度方向的屏幕比例 = cos 55°，只用于 z（飞行高度、弹道）。精灵本身按直立绘制，不再压缩 |
| CX, Y0 | 360, 150 | 画框水平中心；第 0 行上缘的 y。顶栏 96 px 加上远处塔顶的余量（第 0 行塔高 1.4×54=76 px） |

公式（a = 0.75，b = 0.40/15，a′ = a − 0.5b = 0.73667）：

```
s(y)  = a + b·(y − 0.5)
X     = CX + (x − 4.5) · S0 · s(y)
Yg(y) = Y0 + S0 · k · (a′·y + b·y²/2)        # 地面 y，等于对 s 积分，近处行更高
Y     = Yg(y) − z · S0 · s(y) · kz
精灵显示缩放 = s(y) × 单位基准尺寸（例如普通敌人 0.6 格 × S0）
```

- 这是“伪透视”：横向按 s 缩放，行高也按 s 缩放，地面线和两侧收拢与概念图一致，而且有闭式反解。它不是严格的单应变换（严格透视的行高按 s² 变化），好处是远处行不会被压得太扁，点击更容易。【方案】

|---|---|---|---|---|---|---|
| 0 | 150.0 | 171.9 | 0.750 | 54.0 | 44.3 | 144.0 |
| 2 | 240.1 | 263.7 | 0.803 | 57.8 | 47.4 | 128.6 |
| 5 | 387.1 | 413.0 | 0.883 | 63.6 | 52.2 | 105.6 |
| 8 | 548.3 | 576.6 | 0.963 | 69.4 | 56.9 | 82.6 |
| 11 | 723.7 | 754.3 | 1.043 | 75.1 | 61.6 | 59.5 |

### 2.3 反投影（设计坐标 → 地面格）

```
D = (Y − Y0) / (S0·k)
y = (−a′ + sqrt(a′² + 2b·D)) / b          # 一元二次方程取正根
x = 4.5 + (X − CX) / (S0 · s(y))
```

- 只反投到地面（z=0）。点到塔体高处，由 2.5 的“塔体命中框”归到它的塔基，不靠反投。
- 往返误差：格中心反投回来正好是 r+0.5（已验证，计算误差 < 1e-4 格）。

### 2.4 深度排序与分层

| 层 | 内容 | 排序规则 |
|---|---|---|
| L0 地面 | 整张背景图（分 2 块）、路线调试叠加 | 不排序 |
| L1 地贴 | 塔基、碎石地、地面火、蒺藜、射程椭圆、谋略卡吸附圈、选中圈、阴影 | 不排序（都贴地） |
| L2 立体 | 塔、城门、地面敌人、英雄、枪兵 | key = 脚底世界 y（越大越近、越晚画）；同一 y 再按“建筑 < 英雄 < 枪兵 < 敌人”，然后按 x，最后按实体 id，保证稳定 |
| L3 透视轮廓 | 被近处塔挡住的敌人 / 英雄 / Boss 的剪影（tintFill，alpha 0.4） | 跟 L2 同序；只在被挡住时画 |
| L4 飞行 | 斥候鹰（z≈1.0） | 按 y 排；永远压在 L2 上面 |
| L5 弹道 | 箭、石、火球 | 按发射时间排 |
| L6 特效 | 火攻、爆炸、技能、受击光 | 按创建顺序 |
| L7 信息 | 血条、等级牌、飘字、金币 | 永远在最上面，不会被遮住 |

- 遮挡判定：每帧对每个敌人检查同一列附近、脚底 y 比它大的塔（按行分桶，O(敌人数×2～3)），屏幕包围盒有重叠就把它加进 L3。Boss 和刀盾兵描边加粗（PRD 3.1）。

- 同屏可排序对象：60 敌 + 6～16 塔 + 2 英雄 + 最多 9 名枪兵 ≈ 90 个，每帧排一次即可（Phaser 的 `setDepth(key)` 加上层容器）。

### 2.5 射程圈与点击补偿

- **射程椭圆**：取世界坐标里半径 R 的圆，取 48 个点逐个投影，连成多边形。近处那半边会略大，和地面网格严格一致，满足 A15“同一位置射程内的格子相同”。简化画法 rx = R·S0·s，ry = rx·k，只用于调试。
- **命中顺序**：塔或塔基 > 英雄 > 敌人（PRD 3.2）。
- **塔基命中**：先反投到地面格，再在屏幕空间按椭圆判定：
  - 世界半径：0.5 格（第 0–3 行 ×1.3，PRD 3.2）。
  - 屏幕保底：半径 ≥ 22 pt ÷ cssScale（换成设计 px）。例如 375 宽时 cssScale=0.521，保底直径 84.5 设计 px；360 宽时 88 px。
  - 两者取大值，纵向半径再乘 k。
  - 375 宽时最远一行塔基画面只有约 25 pt（格宽 28 pt），保底把点击区补到 44 pt。同行最近两个塔基（p0、p1 相隔 2 格，115.6 px）的命中区不重叠。【已验证：计算】
- **塔体命中**：每座塔有一个以脚底为锚点的矩形（宽 0.9 格，高 1.4 格，乘 s），点到它就算点到这座塔的塔基。几个命中区重叠时，椭圆塔基优先，其次是脚底更近的塔。
- **英雄命中**：0.75 格（PRD v2.3）× s，同样有 44 pt 保底。
- **地面点**（派遣英雄、谋略卡落点）：反投后得到格坐标。谋略卡的预览圈在手指上方 1 格（世界 y−1），并显示吸附圈。
- **调试框**：设置里加一个隐藏开关，画出所有命中区，供 A13 真机截图。

### 2.6 视口适配：只有一处负责缩放

**QA-V013-001 根因（已验证）**

- `app.ts` 的 `fit()` 给 `#frame` 设 CSS `zoom = s`（桌面 1280×800 时 s=0.625）。
- 战斗的 Phaser 配置是 `Scale.EXPAND + CENTER_BOTH`。父容器 `#phaser` 在已经缩过的 `#frame` 里，Phaser 读到的父容器尺寸是缩过的 450×600，就把 canvas 的 CSS 尺寸设成 450×600 左右。浏览器再按外层 zoom 缩一次，canvas 变成 281.25×375 = (720×0.625²) × (960×0.625²)。
- 而 DOM 点击层 `#hit` 只缩了一次，是 450×600。所以画面和点击层错位，环形菜单落在木纹上。
- 927f09c 的修法：`Scale.NONE + NO_CENTER`，CSS 用 `!important` 把 canvas 硬压成 720×960。V0.1.4 QA 复测通过。

V0.1.4 遗留的结构问题：

1. 坐标常数在三处各写一份（`battle.ts` 的 OX/CELL，`app.ts` 的 `cellOf` 和环形菜单原点）。
2. 修法依赖 CSS `!important` 压住 Phaser。
3. canvas 背缓冲固定 720×960，再被放大到设备像素，高分屏会糊。
4. 没有自动回归，只有手工截图。

**V0.2 的结构**

- `view/viewport.ts`（ViewportTransform，**唯一**有权缩放的模块）：
  - 输入：`innerWidth/Height`、`visualViewport`、`devicePixelRatio`、安全区（用一个探针元素读 `env(safe-area-inset-*)`）。
  - 输出：`designW=720`、`designH`、`cssScale`、`renderScale`、安全区（设计 px）、`clientToDesign()`、`designToClient()`。
  - 只有它能写 `#frame` 的缩放，以及 canvas 的 CSS 尺寸和背缓冲尺寸。
- 缩放方式：`#frame` 用 `transform: scale(cssScale)`，`transform-origin: 0 0`，外层 `#fit` 用来占位，替换非标准的 `zoom`。transform 下 `getBoundingClientRect` 的含义在各浏览器一致。【待确认 7；需要在 Chrome、Safari、Firefox 上验证】
- Phaser：`Scale.NONE`，游戏尺寸 = 设计尺寸 × renderScale；主相机 `zoom = renderScale`；canvas 的 CSS 尺寸 = 设计尺寸。renderScale = min(2, cssScale × dpr)，按 0.25 取整，用来保证清晰度。地图点击**不走 Phaser input**，统一由 DOM 点击层调用 `viewport.clientToDesign`。
- HUD 和环形菜单用设计坐标定位，原点由 `projection.worldToDesign()` 给出，不再写死 90/96。
- 守卫：1.4 第 6 条的架构测试，加上第 7 条端到端截图和点击回归。

**各视口的规则**

| 视口 | 处理 |
|---|---|
| 手机竖屏，比 9:16 更高（19.5:9、20:9，例如 390×844、360×800、412×915） | designH = clamp(round(720·vh/vw), 1280, 1560)，宽度填满，**不再上下留黑边**。多出来的高度先给安全区，再平分给顶部天空（背景图要多画 280 px 高）和底栏下方 |
| 正好 9:16 或更宽（平板、桌面浏览器 1280×800） | designH=1280，左右留边，边上用暗色材质 |
| 安全区 | 顶栏下移 insetTop，底栏上移 insetBottom，Y0 同步下移 insetTop。地图背景可以画到安全区里面 |
| 横屏 | 不支持，显示「请竖屏」 |
| 窗口大小变化 / 旋转 | 只有 viewport 重新计算，然后广播；projection 参数不变（地图仍是 720 设计宽） |

【待确认 6】高屏手机去掉黑边要多画背景，也可以继续用 V0.1 的固定 720×1280 加黑边。

## 3. 素材规格与性能预算

### 3.1 通用约定

- **锚点**：所有地面单位、塔、城门的锚点都在**脚底中心**（origin 0.5, 1.0），排序和缩放都按脚底；飞行单位的锚点在身体中心，地面另画一个阴影。
- **基准尺寸**：画面上的尺寸 = 基准尺寸 × s(y)。出图分辨率按最近一行（s=1.15）× renderScale 2 来定，再加 10% 余量；远处靠 2048 正方图集（2 的幂）开 mipmap 缩小，不用单独做 LOD 档。【Phaser 4 的 mipmap 开关未验证；如果不行，就退回两档 LOD（1×、0.6×）】
- **光照**：统一左上方来光，影子落在右下，和 B 概念图一致。
- **朝向**：M1 / M1b 的路线只有向下、向左、向右三种方向（已验证：读地图 JSON，37 个路点没有向上走的）；鹰从入口直线飞向城门，也是向下。所以第一章只画“前 3/4（朝下）”和“侧面”两个方向，左右镜像；**背面第一章不做**，第二章有向上的路线时再补。
- **格式**：源文件用 PNG 进美术仓（不进游戏仓库）；构建时打成图集。带透明的用 WebP（质量 85，带 alpha），背景用 WebP 或 JPEG；单张 ≤ 2048×2048。
- **命名**：`{类}_{id}_{动作}_{方向}_{帧两位}`。类：t 塔、e 敌人、b Boss、h 武将、u 枪兵、fx 特效、ui 界面、bg 背景。方向：f 前、s 侧。例如 `e_luanbing_walk_f_03`、`t_jianlou_lv4a_idle_01`、`h_huangzhong_skill_s_05`。图集名 `atlas_{组}_{序号}.webp` 加同名 `.json`（Phaser 用的 JSON Hash 格式）。用一个脚本检查命名和帧数，不合规就拒绝打包。
